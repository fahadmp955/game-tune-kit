# GameTuneKit Utility #01 — LTV Calculator

## Part A — Reference / Research

### Reference product

**The Game Scientist — Cohort Retention & LTV Simulator**

Source: https://thegamescientist.com/tools/ltv-simulator/

TGS describes the tool as fitting a mathematical power-law retention curve:

\[
R(t) = a \times t^{-b}
\]

to observed cohort retention, then using the resulting retention curve to estimate active lifespan and cumulative LTV.

### TGS inputs

**Basic mode**
- D1 retention %
- D7 retention %
- D30 retention %
- Daily ARPU / ARPDAU
- LTV horizon: 90 / 180 / 365 days

**Advanced mode**
- D1
- D3
- D5
- D7
- D14
- D21
- D30
- D90
- Daily ARPU / ARPDAU
- LTV horizon

TGS also offers genre benchmark presets.

### TGS outputs
- Estimated LTV
- Expected active lifespan
- D365 survival
- Fitted decay coefficient `b`
- Retention curve
- Cumulative LTV curve

### TGS methodology

TGS fits:

\[
R(t)=a t^{-b}
\]

against the supplied retention observations.

Once the curve exists:

\[
ActiveDays(H)=\sum_{t=1}^{H}R(t)
\]

where retention is represented as a decimal probability.

Then:

\[
LTV(H)=ARPDAU\times ActiveDays(H)
\]

# Part B — GameTuneKit PRD

## 1. Product

**GameTuneKit LTV Calculator**

**Utility ID:** `UTIL-001`  
**Family:** Acquire / Design  
**Parent modules:** Pricing & Monetisation; Game Intelligence  
**Layer:** L0 — Generic/Open

No login, SDK, telemetry or GameTuneKit integration is required.

## 2. Product goal

Answer:

> **Given my game's retention and monetisation, how much is an acquired player worth over time?**

The user should be able to get a useful answer in **under one minute**.

It should also answer:
- How long does the average acquired player remain active?
- What is my expected LTV at D30/D90/D180/D365?
- How much does the long retention tail contribute?
- How quickly is my cohort decaying?
- What happens to LTV if retention or ARPDAU improves?

## 3. User

Primary users:
- Game producer
- Product manager
- Monetisation designer
- Growth/UA manager
- Studio founder
- Economy designer

The calculator must **not require statistical knowledge**. Terms such as decay coefficient should be explained rather than assumed.

## 4. Calculator modes

### Basic — Default

| Input | Type | Default | Range |
|---|---|---:|---:|
| D1 Retention | % | 35 | 0–100 |
| D7 Retention | % | 15 | 0–100 |
| D30 Retention | % | 7 | 0–100 |
| ARPDAU | Currency | $0.12 | ≥0 |
| Projection Horizon | Select | 365 | 90 / 180 / 365 |

### Advanced

Adds D3, D5, D14, D21 and D90.

Final set:

`D1 / D3 / D5 / D7 / D14 / D21 / D30 / D90`

ARPDAU and horizon remain unchanged.

## 5. Validation

Advanced retention must satisfy:

```text
100 >= D1 >= D3 >= D5 >= D7 >= D14 >= D21 >= D30 >= D90 >= 0
```

Only populated checkpoints participate.

Basic:

```text
D1 >= D7 >= D30
```

If violated:

> Retention normally decreases over time. Check these values before calculating.

Do not silently alter user data.

ARPDAU:

```text
ARPDAU >= 0
```

Decimals are allowed.

## 6. Retention model

Fit:

\[
R(t)=a t^{-b}
\]

using:

\[
\ln R = \ln a-b\ln t
\]

Perform ordinary least-squares regression against all valid retention checkpoints.

Store:

```text
a
b
R²
```

GameTuneKit should expose R² to show whether the approximation fits the supplied cohort.

## 7. Daily retention projection

Generate `R(1)...R(365)`.

Bound projected retention:

\[
R'(t)=min(1,R(t))
\]

Do not round internally.

## 8. Active lifespan

\[
ActiveDays(H)=\sum_{t=1}^{H}R(t)
\]

Display **Expected Active Days**, to one decimal place.

Tooltip:

> The expected total number of active user-days generated by one acquired player over the selected period.

## 9. LTV

\[
DailyValue(t)=R(t)\times ARPDAU
\]

\[
LTV(H)=\sum_{t=1}^{H}DailyValue(t)
\]

Equivalent:

\[
LTV(H)=ARPDAU\times ActiveDays(H)
\]

Calculate internally through D365 regardless of selected display horizon.

## 15. Scenario controls

### What if?

Two sliders:

**Retention improvement:** `-20% → +50%`  
**ARPDAU improvement:** `-20% → +50%`

Show:

```text
Current LTV       $2.64

```

For V1, retention improvement uniformly multiplies every retention checkpoint. Cap at 100%. Refit the scenario retention curve.

## 16. Diagnostic interpretation

### D1 — Acquisition → Activation
Can suggest onboarding, first-session or expectation-mismatch issues.

### D1 → D7 — Habit formation
Shows whether players establish the core loop.

### D7 → D30 — Mid-term retention
Shows whether content and progression sustain engagement.

### D30+ — Long tail
Shows whether the game creates durable engagement.

Do not automatically classify values as good/bad until GameTuneKit has trustworthy benchmark data.

\[


### Test B — Zero ARPDAU

Valid retention + `ARPDAU = 0` → all LTV outputs equal `$0`; retention outputs remain valid.

### Test C — Invalid retention

```text
D1 = 30
D7 = 40
D30 = 10
```

Show validation warning and do not calculate until corrected.

### Test D — Scenario

At 0% retention and 0% ARPDAU adjustment, scenario LTV exactly equals baseline.

### Test E — URL state

Copy URL, open in clean browser; inputs and calculated results reproduce exactly.

## Product Direction Note

The GameTuneKit implementation deliberately goes beyond a single LTV output by adding:

- D30 / D90 / D180 / D365 LTV milestones;
- LTV composition by lifecycle period;
- fitted-model transparency including R²;
- a simple retention and ARPDAU What-If model.

These additions materially improve the calculator's usefulness while adding relatively little implementation complexity.

This level of specification should be the target before handing each GameTuneKit utility to Codex.
